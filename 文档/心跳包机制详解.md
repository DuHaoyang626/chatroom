## 概述

心跳包（Heartbeat）是维持WebSocket长连接稳定性的重要机制。本项目通过定期发送心跳包来检测连接状态，确保客户端与服务端之间的连接保持活跃，及时发现并处理连接异常。

**文件位置：** `c:\code\project\chatroom\dot-chat-web\src\main\webapp\js\im\imHandler.js`

```javascript
/**
 * 发送心跳包
 */
function sendHeartbeat() {
    if (websocket && websocket.readyState === WebSocket.OPEN) {
        let message = {
            msgType: MsgType.HEART_BEAT,
            msgBody: {
                content: 'ping'
            }
        };
        websocket.send(JSON.stringify(message));
    }
}
```

## 5. 心跳包机制的工作流程

### 5.1 完整的心跳交互流程

1. **客户端发起心跳**：前端每30秒发送一次心跳包（HEART_BEAT消息）
2. **服务端接收处理**：后端接收到心跳包后立即发送响应（HEART_BEAT_RESPONSE消息）
3. **连接状态检测**：如果60秒内没有收到任何消息（包括心跳包），服务端会认为连接超时
4. **异常处理**：连接超时或异常时，服务端会主动断开连接，客户端会尝试重连

## 6. 心跳包机制的技术特点

### 6.1 主要特点

1. **双向通信**：客户端发送心跳包，服务端发送心跳响应
2. **定时机制**：客户端每30秒发送一次心跳包
3. **超时检测**：服务端60秒超时检测机制
4. **自动恢复**：连接断开后自动重连机制

### 6.2 技术优势

1. **连接保活**：有效防止网络代理或防火墙关闭空闲连接
2. **故障检测**：及时发现网络异常或服务异常
3. **资源优化**：避免无效连接占用服务器资源
4. **用户体验**：保证消息的实时性和可靠性

## 总结

本项目的心跳包机制通过前后端协作，实现了稳定可靠的WebSocket长连接维护。客户端定时发送心跳包，服务端及时响应并监控连接状态，确保了聊天室应用的实时通信质量和用户体验。这种设计既保证了连接的稳定性，又避免了不必要的资源浪费，是实时通信应用的标准实践。
